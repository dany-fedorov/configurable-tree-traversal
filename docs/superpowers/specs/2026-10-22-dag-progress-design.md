# DAG progress and reconciliation design

This implements approved roadmap slice S2 on merged S1 (00f08ed). WBS remains the owner of durable facts, attempts, claims, clocks and storage providers. CTT supplies in-memory graph scheduling through its existing hint adapters. No separate planDag input model or persistence provider is introduced.

## Accepted requirements

### Work success versus subtree completion


Model `W(v)` for initial work success and `C(v)` for successful descendant completion. Normal dependencies require W; `dependsOnComplete` requires C. C requires W, closed discovery, and C for each retained child. Shared children satisfy each parent obligation once.

Add `completedWork?: ReadonlySet<VertexId>` to graph-source DAG configuration. On accepting a seeded vertex, skip its `ON_READY` visitor chain, satisfy W, and still discover/process descendants. Do not jump directly to `COMPLETE`. Suppress the corresponding initial event as well; completion events remain normal structural events once the subtree actually completes. Hosts using fresh planning ticks execute no lifecycle callbacks, so these are not repeated external activities.

Copy the seed when making a runner. Preserve arbitrary in-process IDs. Reject seed options in tree-source mode, reject conflicts with injected continuation state, and report unused seed IDs after discovery closes. Durable hosts map stable string IDs to the current run's graph revision. Any future explicit subtree-completion seed requires descendant-closure validation; it is not necessary for the initial feature.

### 2. Unified hints API, deferred work and host admission

**Accepted direction (2026-10-21):** keep one public hints API. The former `planDag(DagPlanInput)` proposal is superseded: it described a useful question (ready activities and blockers) but introduced a second public graph representation. No separate `DagPlanVertex` model, scheduler entry point or `planDag.ts` export is required. Internal pure bookkeeping may be shared behind the existing runners.

The host supplies a revision-consistent snapshot through the existing hint adapter, seeds accepted completed work, advances graph discovery/validation without executing business activities, and reads the DAG runner's ID-keyed `summary()`. A deliberate inspection visitor returns `DEFER_READY`; it must never return successful no-op work. This runner construction invokes only the supplied snapshot adapter and inspection hooks, which must be deterministic and free of business effects. `summary()` itself invokes no user callbacks or resolvers and mutates nothing.

Proposed additions within the current API:

- `DEFER_READY` leaves work uncommitted; no output or dependency success is published. A deferred vertex is not necessarily a running external attempt. Track deferred readiness separately from admitted/in-flight host work.
- `runner.settle(id, outcome, expectedGeneration)` reports host-accepted completion to a retained runner. The generation/settlement token binds the report to the current runner and logical execution; stale/cancelled/unknown reports refuse. Repeated identical settlement is idempotent; conflicting settlement refuses. A late old attempt cannot complete a repaired/retried activity. Final naming/signature is settled with existing runner conventions, not a new public scheduler model.
- `summary()` returns detached read-only ID-keyed status counts, dependency-ready/deferred IDs, runner in-flight IDs, unmet prerequisite IDs, work/subtree completion, structured diagnostics, and discovery completeness. Original IDs/output values retain identity. Host running/wait/retry state is overlaid by the coordinator before admission; kernel readiness alone is not permission to run.
- A synthetic root supports multiple sources without leaking a fake activity into events, `ON_COMPLETE`, summaries or path results. Root discovery must not impose success dependencies on real sources.

**Discovery contract:** deferring work must not prevent the snapshot's topology from being fully discovered and validated. For WBS, the adapter supplies the complete declared vertex catalog, including disconnected components and cycles with no source. Validate duplicate IDs, missing references, seed validity and combined work/subtree cycles before admission; seeded successes cannot hide a cycle. Inspection reaches a bounded quiescent point even with deferred work and publishes no success. A lazy runner reports partial discovery explicitly; its summary must not claim a complete global frontier. Add a test where deferring a parent would otherwise hide a child.

**Reconciliation:** rebuild the runner on a new tick/restart from accepted durable facts; no live runner or deferred token is persisted. A retained runner may settle only after WBS accepts the guarded business result. Otherwise rebuild from that result on the next tick. A graph revision change discards the old runner and invalidates its settlement handles. Pending candidates whose success prerequisites are satisfied can be admitted; running/waiting/retry-wait/terminal failures are excluded by durable host facts. A due retry is made pending by the host using its persisted deadline. Enumerating a candidate changes no completion fact.

Example expectations: after design succeeds, backend and frontend appear together; deferring backend does not release verification; after only backend succeeds, verification still waits; after both succeed, verification becomes ready. A failed claim cannot accidentally consume a candidate or report success. Capacity reservations and exact-identity claims are still host/WBS transactions, not runner operations.


## Concrete API and lifecycle decisions

- Graph-source runner options: `completedWork?: ReadonlySet<VertexId>`, `discovery?: 'lazy' | 'eager'` (default lazy), `syntheticRoot?: boolean` (default false). Copy seeds for each runner, never freeze caller IDs or mutable values. Reject these options in tree-source mode; reject enabled progress options with injected continuation containers/state. Undefined optional values mean absent. Eager discovery is opt-in, preserving legacy FIFO and child-rewrite timing by default.
- Seeded work skips initial callbacks/events, satisfies W, and still expands children and awaits C normally. Track unused seed IDs and reject them once discovery is complete, before visits in eager mode. Full graph validation uses declared dependencies, so seeded success cannot erase a cycle.
- Eager mode resolves all reachable hints before admitting any user visitors, including blocked vertices. The WBS adapter puts its complete declared catalog in a synthetic root's hints, including disconnected cycles. Duplicate catalog IDs, unresolved dependencies, cycles and unused seeds fail before activity admission. Shared descendant references remain legal. Unsupported `priority` and `dependsOnComplete` metadata reject explicitly pending later slices.
- The synthetic root is internal structure only: no callbacks/events, public vertex counts, summary entries, or paths include it. Its children do not inherit an implicit work dependency on it. The public resolved-graph view has no single root; parents/paths and saved snapshots omit synthetic catalog edges. Explicit catalog membership retains a listed vertex even after its sole real parent is deleted. Public paths follow the remaining forest: a catalog-listed shared child with real parents a/b has paths [a,child] and [b,child], not an extra [child] path. noRoot remains a no-op because there is no designated public root; noSelf removes the target. Active and saved views agree. Catalog duplicate checking applies to repeated root entries, not ordinary shared children. Explicit stable IDs are required for catalog entries. The adapter remains the authority that the catalog covers its whole domain. Synthetic root identity is internal; ensure it cannot collide with a real catalog ID. Eager mode rejects child-hint rewrites and subtree-disabling commands after discovery, since those invalidate the inspected topology; data rewrites and existing deletion behavior remain supported.
- Export `DEFER_READY` as a unique symbol accepted from DAG ON_READY visitors. A deferring callback ends the initial chain without success/event; uncommitted buffered commands and remaining visitors are discarded. Previously committed mutations/external effects cannot be undone, so inspection uses a sole deterministic deferring visitor. Reject the sentinel in tree traversal and completion callbacks. Deferred work has no physical callback permit or active chain. Lazy deferral may expand the deferred vertex's own hints; only eager discovery promises catalog-wide validation/frontier completeness.
- Expose `runner.settle(id, outcome, expectedGeneration): boolean`, where outcome is `{ ok: true } | { ok: false; error: unknown }` and generation is an opaque symbol issued for that deferred vertex in that runner. True means first accepted settlement; false means identical replay. Reject unknown, stale, deleted, cross-runner or conflicting reports. Failure equality uses Object.is(error). Success commits W exactly once and publishes its normal ON_READY event if requested, without replaying visitors; seed-based reconstruction still suppresses seeded initial events. Failure preserves the exact original thrown value and existing fail-fast behavior. Output transport belongs to S4. A halted runner remains resumable; halt is not cancellation. Notify async execution after accepted settlement so active consumers can progress.
- Once discovery/physical callbacks/events reach quiescence with legitimate deferred blockers, run()/iteration returns HALTED rather than throwing or hanging. Invalid graph causes still fail. The host can inspect, accept business progress, settle and call run() again. No implicit polling loop or business execution occurs in summary().
- Export a detached readonly `DagSummary` from both runners: discovery mode/completeness, counts, ID-keyed vertex map, ready/deferred/in-flight IDs, completed-work and completed-subtree IDs, unused seed IDs, and structured S1 diagnostics. Vertex entries include id, work state (pending/ready/running/deferred/succeeded), subtree completion, unmet prerequisite IDs, and generation only for deferred work. Ready means unsatisfied business work whose graph prerequisites are met, including deferred candidates; host running/wait/retry overlay remains outside CTT. In-flight represents runner work chains, never external host attempts.
- Summary collection containers are copied/read-only; original IDs remain identical. summary() invokes no callbacks, resolvers or mutating scheduler operations. Before initial discovery it is explicitly incomplete. Deferred blockers alone are not invalid graph diagnostics. On partial lazy discovery, diagnostic unknown IDs mean not yet discovered.
- Reuse GraphScheduling for all dependency semantics; do not create a second scheduler. Extract a small progress-state helper if useful for seeds/tokens/reporting. A speculative DependencyIndex extraction is unnecessary unless actual sharing demands it.

## Compatibility and tests

Preserve all six existing traversal families, tree adapters, arbitrary SameValueZero IDs, default FIFO, exact thrown values including null/undefined, iterator halt/resume, historical imports and Node22/24. Keep 100% statements/branches/functions/lines. Test seed parent/pending child, diamond snapshots, deferred parent discovery, invalid seeded cycles, disconnected cycles, same-ID duplicate catalog entries, generation conflicts/replays, arbitrary IDs, active async settlement, no-callback summaries and reference frontiers over generated small DAGs. No storage, database, clock or WBS APIs in core.
