# Fable API clarity review disposition

The original [API clarity review](2026-10-26-api-clarity-fable-review.md) is preserved verbatim. This record disposes of its 20 numbered observations against the approved [bounded design](../specs/2026-10-26-fable-api-clarity-design.md). All changes below are in the unreleased checkout; published 0.11.0 behavior is a separate release fact.

| # | Disposition | Implementation evidence or reason |
| --- | --- | --- |
| 1 | Implemented in scope | Tree and object-hook omissions are plain `{ kind: 'omitted' }`; graph/prerequisite omissions require literal `satisfiesDependencies: true` because omission satisfies W and C. See `src/core/TraversableTree.ts`, `src/core/drivers/normalizeSourceResult.ts`, `docs/reference.md`. The suggested optional graph acknowledgement was rejected: it would conceal a milestone decision. |
| 2 | Implemented | Preparation, definition preparation, composition and revision return `invalid.issues`; source milestone diagnostics are one `milestone` issue. Callback-thrown values remain exact exceptions. See `src/traversals/dag-traversal/lib/PreparedDag.ts`, `prepareDag.ts`, and `docs/reference.md`. |
| 3 | Implemented in scope | All collection selectors use `dependsOn` / `dependsOnComplete`; four adapters reject retired selector keys before callbacks. Query milestone tags and relation/diff aspect names retain their distinct meanings. See `src/sources/types.ts`, `docs/reference.md`. |
| 4 | Justified difference; documented | `walkSourceFrom` owns and validates a finite catalog, mapping `{ to, data }` to lazy links `{ target: { vertexId: to }, data }`. A lazy source can hydrate its target inline; catalog links cannot have competing hydration authority. See `docs/reference.md` and `docs/agent-workflows.md`. Found resolutions contain data; found event targets contain a resolved vertex. |
| 5 | Guidance implemented; phase rename deferred to major version | `ON_READY` visitors run before work, while `ON_READY`/`workCompleted` events report committed W, including deferred settlement. README, workflow/reference/migration guides, example and `DagEvent` JSDoc lead dispatch from frontier tickets. Published event timing remains unchanged. A separate emission-phase vocabulary needs a future major design. |
| 6 | Implemented | Unreleased coordinator `fail` alias is removed; `failTraversal` is the sole fatal settlement method. See `src/traversals/dag-traversal/coordinateDag.ts` and migration guide. |
| 7 | Justified existing inference | `new GraphWalk({ source })` infers Data, Edge and ID together. Adding `ID = unknown` to partially explicit type arguments would choose unknown instead of inferring ID from the source. Keep inference and explicit three-argument annotation when needed. |
| 8 | Documented projection | `PreparedDag.vertices` is a live-child convenience projection that drops omission slots; `definition` is the faithful ordered reconstruction/revision value. See reference, migration guide and public JSDoc. |
| 9 | Justified existing enum | `GraphWalkPhase` matches the tree/DAG enum pattern; event `kind` remains a string discriminant. The reference now names enum values beside selectors. |
| 10 | Documented roles | `summary()` gives progress, `inspectDag()` gives captured W/C dependency explanations, and `inspect()` gives execution/iterator state. See ticket guidance in reference and workflow guide. |
| 11 | Deferred convenience | Session factories intentionally expose host-only external settlement. To run visitors, create a runner with visitors and wrap it with `coordinateDag` / `coordinateDagAsync`; no correctness gap requires a new session option. |
| 12 | Justified replacement | Walking `configure({ limits })` atomically replaces the limits record, allowing bounds to clear; phase selector fields patch independently. A recursive merge/undefined reset would need a separate configuration design. |
| 13 | Deferred breaking vocabulary work | Published `DagVertexProgress.id` and diagnostic `dependencies[].id` retain their fields; duplicate `vertexId` aliases would increase ambiguity. Ticket/definition identity remains `vertexId`. |
| 14 | Published names retained | Explanations use completion for milestone C, while established `subtree` fields and `subgraphCompleted` event kind remain. A wholesale naming change is future-major work. |
| 15 | Documented | `hasSingleSink` counts resolved vertices without structural children, ignoring W/C dependency edges. Empty is false; a single leaf is true. See reference and public JSDoc. |
| 16 | Documented representation boundary | Definition omission slots use `identity: { vertexId } \| null`; low-level `ChildSlot` uses own `vertexId` presence. Both preserve known `undefined` versus anonymous omission. See materialized definition reference. |
| 17 | Documented | Walking edge-event `source` is the found source vertex, while `depth` is the target route depth. See walking record table and adjacent reference text. |
| 18 | Deferred encapsulation | Mutable `DagTraversal.icfg` / `visitors` are published low-level fields. Guidance prefers prepared/session facades; changing encapsulation needs a versioned redesign. |
| 19 | Compatibility retained | Trailing DAG ID generic preserves existing T/R parameter order. Typed sources usually infer IDs; explicit calls may repeat the rewrite type. No generic reorder. |
| 20 | Justified adapter distinction; documented | `graphFrom.children` returns catalog IDs; `forestFrom.children` returns nested records. The selector table now states both at point of use. |
