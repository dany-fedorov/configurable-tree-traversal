## New contradictions or regressions introduced by the documentation changes

These are the same remaining issues identified in the rows above, not additional undisclosed blockers. No Critical issue was found.

**N01 — Important: the options matrix admits two graph-only settings too broadly (D18).** `docs/reference.md:191` explicitly includes DAG tree-source mode in the matrix, then `200` and `201` label discovery/syntheticRoot simply “DAG”. Unlike completedWork at `204`, these rows do not say that eager discovery and a true syntheticRoot require a fresh graph-source runner. Both sync and async constructors reject those values in tree-source mode (`src/traversals/dag-traversal/lib/DagTraversalRunner.ts:124`–`132`; `src/traversals/dag-traversal/lib/AsyncDagTraversalRunner.ts:129`–`137`). This is a plausible copy-from-matrix runtime failure. Add the value-specific restrictions, preserve lazy/false behavior, and explicitly distinguish runner.prepare(), which can prepare a fresh tree-source DAG runner.

**N02 — Minor: some generated owning-contract/example links are semantically wrong (D08).** The broad matcher at `scripts/build-api-index.cjs:77`–`84` sends all source declarations to a tree-only example and matches ChildHintTransformer, DagEvent and filtered visitor helpers as ordinary visitor commands. Concrete outputs are `docs/api-index.md:1347`, `1795`, `1824`, `6736`, and `6749`. The filtered helper's true local contract is `docs/reference.md:651`–`667`; the linked commands recipe never invokes the helper. The transformer semantics live in `docs/reference.md:193`, and committed DAG event semantics are distinct from visitor command timing. Add explicit overrides ahead of broad source-pattern matching, use family-appropriate executable examples, and test these destinations. Index freshness and link existence cannot establish semantic relevance.

**N03 — Minor: “newly dispatchable” labels a persistent frontier (D13).** `docs/agent-workflows.md:113` labels the table as new dispatchable work, but `tests` appears in both the initial row (`115`) and the next row (`116`). The runtime evidence correctly represents outstanding ready/deferred work, and the guide already explains reusable observations at `129`–`131`. Rename the column to “Current ready/deferred work” or “Work available after advance”; do not alter the correct trace values.
