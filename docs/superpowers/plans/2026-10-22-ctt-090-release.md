### Task 2: Measure discovery and repeated summaries

**Files:** New scripts/benchmark-dag.cjs, meaningful small-fixture test(s) under tests or scripts, docs/performance/2026-10-22-dag-baseline.md plus machine-readable results under docs/performance; package.json benchmark:dag command and Development documentation.

**Interfaces:** Public DagTraversal, DagTraversalOrder.ON_READY, DEFER_READY, completedWork/eager/syntheticRoot and summary(). Optional explicit library-path argument permits measuring the freshly installed npm package; default built dist remains reproducible locally. Report loaded artifact path/version, Node/platform/CPU, V/E, shapes, seeds, repetitions and exact commands.

- [ ] Define deterministic dependency chain, independent/wide, layered diamond, sparse and bounded-dense fixtures. All edges point from earlier to later IDs; dense fan-in is bounded/documented to keep10,000vertices tractable. Build full catalog with explicit IDs, no business visitors.
- [ ] Write meaningful RED small-fixture checks for vertex/edge counts, expected frontiers with empty and prerequisite-closed prefix seeds, and independent Kahn readiness parity. Assert repeated summary does not invoke resolvers or change completion/readiness; assertions stay outside timed regions. Validate bad CLI counts and keep memory bounded; no timing thresholds.
- [ ] Implement a minimal CLI with positive integer vertex/sample/summary-iteration controls. Separate fixture construction, runner construction, eager discovery+validation to first inspector callback, run-to-quiescence and repeated summary timing. Label overlaps: run includes discovery and deferral admission; first-callback interval includes traversal setup and validation. Warmup/sample policy must be explicit; exclude warmups from reported medians/ranges.
- [ ] Include a handwritten independent Kahn baseline over equivalent prerequisite facts and supplied seeds. Clearly label that it measures dependency indexing/frontier only, not CTT resolver/lifecycle/identity/validation features; no misleading speedup claim. Record E as well as V, callback counts and optional memory deltas with limitations.
- [ ] Run correctness checks and fresh full npm run check after harness changes. Measure representative1,000and10,000vertex cases with documented sample counts and summary repetitions. Use the published0.9.0 package after publication; if auth remains blocked, record candidate measurements honestly and rerun against the registry installation when available.
- [ ] Save raw results and a concise report of observed scaling/bottlenecks/limitations. Propose follow-ups only; do not optimize runtime or add graph/workflow features. Commit; parent reviews/pushes/merges evidence.

**Deliverable:** Reproducible artifact-linked baseline and generic follow-up candidates, not a performance guarantee or an optimal-scheduling claim.
