## Scope and boundaries

CTT owns generic tree/graph discovery, work/completion dependencies, callback scheduling, traversal lifecycle, diagnostics, and in-memory progress. Keep task types, agent dispatch, business priority/outcomes, attempts/retries, claims, artifact policy, and durable storage in the host. `$data` is opaque caller data; `$childHints` contains opaque discovery hints. `$d`/`$c` inputs and accessors are removed; Vertex fields and serialization use `$data`/`$childHints`. There is no public `planDag`, storage-provider port, durable runner checkpoint, or built-in LLM integration.

Dependency edges and structural child edges are different. Under default `afterWorkReadyChain`, normal `ON_WORK_READY` completion satisfies W; committed `ON_SUBGRAPH_READY` satisfies C. Use `workCompletion: 'externalSettlement'` for host-controlled work, including zero/filtered callbacks; prepare a fresh runner for an eager validated preview, then run and dispatch from `summary().awaitingSettlement` records with atomic generation guards. Preparation freezes topology; run adopts discovery without replay. Dispatch from `advance().workTickets` or enabled pre-work visitors. DAG event kinds `workCompleted`/`subgraphCompleted` are committed W/C observations; callback-before-commit and event-after-commit timing remain. Deferred `workCompleted` events emit on settlement; seeds synthesize no work event. Explicit sole `DEFER_WORK_COMPLETION` ends a chain early; `PAUSE_TRAVERSAL` pauses it. `getStopReason()` distinguishes pause from awaiting settlement. Graph sources default to `rootWorkDependencies: 'honor'` and `dependsOnWorkDefault: 'none'`; express execution dependencies explicitly. Explicit graph dependency policies reject on TreeSource inputs; tree order is preserved. Deletion commands follow the runner family: `DELETE_TREE_SUBTREE` or `DELETE_DAG_VERTEX_CASCADE`. Stored-tree deletion is `deleteSubtree`, revision removal is `removeVertexDeclaration`, and multi-entry definitions use ordered `roots` slots. `SKIP_REMAINING_CHILDREN` skips pending local expansion; `SET_VISITOR_CHAIN_STATE` accepts `{ state }` for the current phase chain. Source callbacks use tagged `found`/`omitted` results; only prerequisite lookup accepts `missing`. `emitEvents` and `visitorPhases` select events/callbacks independently and patch field-wise. Flat visitors sort by priority before batching; explicit ordered groups own their batching policy. `commandCommitMode` is independent of async concurrency. Tree sources forbid graph metadata. Prefer `resolveChildHook`, typed object patches, `getResolvedTreeView()`, `getRefId()` and graph `requireVertexId`/`getVertexRefById`; ordinary tree/DAG observations expose canonical VertexHandle/VertexView facets, frozen detached hint/topology collections, and shallow caller payload identity. Tree contexts use resolvedTreeView; graph contexts use resolvedGraphView/getResolvedGraphView. Ordinary runners expose no live mutable store or independent traversal-root predicate. Synthetic entry source parents have both parent fields null; tree parents stay non-null. Use family-safe execution capabilities and cooperative `requestPause`; requests drain admitted callbacks without cancellation before acknowledgement. Rewrite output uses present/absent tagged results and defaults to unknown; `rewriteObjectAs` asserts output and `getOutputResult()` requires FINISHED. The rewrite helper owns its source. Visitor registration queries return detached records with shared callbacks/group metadata. Graph ID generics trail T/R (visitor ID follows phase); typed live results require own IDs and public views hide synthetic holders. Runner constructors, raw containers/state, normalized options and deep engine paths are private; use public factories, capability interfaces and the explicit supported entry points. Diagnostic edges are original milestone constraints, waiter waits for prerequisite; structural cycle componentVertexIds are SCC membership; discovery cycleWitnessVertexIds are ordered closed witnesses. Settlement generations are local symbols; reconstruction uses host-accepted `completedWork` facts. `inspectDagMilestones` captures observational milestone snapshots. Inspection uses ready/chain `phase`, chain `state`/`visitorIndex`/`executionOptions`, and request `operation`; graph `visitStage`/`getVisitStageOf` describes scheduling boundaries, separately from callback counts, DAG W/C, and runner lifecycle status. `PreparedDag.liveVertexSummaries` is a live-child convenience projection; `PreparedDag.definition` preserves ordered slots/omissions; mapDagFragmentIds maps fragment IDs explicitly and compose structural links separately from W/C wires. `reviseDag` validates an ordered batch against a private candidate and returns a fresh prepared DAG plus a shallow diff; old sessions, tickets and admitted callbacks remain local and no completion facts migrate.

`MaterializedDagInput` and `materializeDagInputFromRecords`/`materializeDagInputFromRoots` (plus Async counterparts) return `{ traversableGraph, syntheticRoot: true }` envelopes. Pass or spread the entire input; `DagDiscoverySource` is the actual protocol. Walking materializers return actual `GraphWalkSource` protocols and retain source names.

Walking uses `GraphWalk`/`AsyncGraphWalk` sources with explicit target wrappers; it does not consume arbitrary tree/DAG sources directly. Revisit, callbacks and emission are independent. First admitted resolution (including omission) wins; rejected links do not seed cache. Default once preserves parallel/back edges; bounded route modes report summary outcomes. All family selectors filter at delivery, including buffered records and deferred settlement events; callback admission snapshots stay independent. Chain inspection emitEvents is historical, while top-level executionOptions governs delivery. Callbacks are serial; own concurrency options reject. Consumer iterator return pauses; terminal runner close disposes open source iterators in reverse acquisition order. Closing FAILED rethrows the exact retained error without repeated cleanup; overlapping async closes share a promise. Configure replaceLimits records replace prior limits records and merged validation is atomic. `GraphWalkDagRelation` labels are adapter-owned/detached; caller edge data retains identity. General execution capabilities default to `ExecutionInspection` and `EmissionKind<Phase>`, preserving family phases. Concrete tree/DAG runners use `TreeDagExecutionInspection`; walkers use `GraphWalkInspection`. Tree callbacks use `TreeVisitor`/`AsyncTreeVisitor`, with structural source protocols and no empty runtime bases.

## Commands and validation

```sh
npm ci
npm run check
npm test -- tests/dag-prerequisite-resolution.test.ts
npm run tsfile -- examples/agent-orchestration-example.ts
npm run verify-examples
npm run verify-package
```

`npm run check` covers typechecking, lint, all source tests with 100% coverage, examples, build, packed runtime/type consumers, and benchmark/generator checks. For behavior changes, reproduce the issue with a focused public regression, then run the full check. For documentation changes, execute new/changed examples, verify relative links/anchors and packaged guides, and use the standard check before integration. Do not weaken coverage to pass.

The async runtime shares a state-machine core with sync runners; test affected sync/async and tree/graph families when changing shared behavior; include walking when changing common capabilities/selectors/registration. Preserve arbitrary ID identity and exact error values. ESM and CJS must share constructors, sentinels, namespaces, and declaration identity; verify packed consumers, not just source imports.

## Documentation upkeep

Keep README concise and autonomous-agent use cases first. Put integration decisions in `docs/agent-workflows.md`, detailed contracts in `docs/reference.md`, and navigation in `docs/index.md`. Keep runnable examples under `examples/`; the example verifier discovers every top-level `.ts` file. Regenerate `docs/api-index.md` with `npm run docs:api` after public declaration changes; the package verifier rejects drift. Update package `files` entries when adding a consumer guide so npm readers can follow relative links. Link repository-only examples/history through GitHub from packaged docs. Preserve existing public section anchors when moving content.

Do not infer publication authorization from test/build commands. Release and external-write actions follow the user's current instructions. Preserve unrelated local changes and never include credentials in examples or logs.
