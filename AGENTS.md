## Scope and boundaries

- **Host versus CTT:** CTT owns generic discovery, W/C dependencies, callback scheduling, lifecycle, diagnostics, and in-memory progress. Keep task meaning, agent dispatch, business outcomes, retries, claims, artifact policy and durable storage in the host. `$vertexData` and `$childDiscoveryHints` contain opaque caller values; preserve their shallow identity.
- **Builders, runs and captures:** Builder classes capture source/options/registrations. `patchOptionsForFutureRunners` affects future independent runners; `createIndependentRunnerFromCurrentOptions` starts separate progress. `runUntilSuspendedOrTerminal` and `runAndIterateObservationEventsUntilSuspendedOrTerminal` execute and can return suspended. `captureExecutionSnapshot`, `captureProgressSnapshot`, and `captureMilestoneSnapshot` only observe.
- **DAG W/C and settlement:** Structural child edges differ from execution prerequisites. `workWaitsForWorkOf` waits for W; `workWaitsForSubgraphCompletionOf` waits for C. Default `afterWorkReadyVisitorChain` completes W on normal work-chain return; `requireExternalWorkSettlement` defers even zero/filtered callbacks. Use a fresh runner's `discoverValidateAndFreezeTopology` for validated preview, then execute without replay. Dispatch session `runUntilWorkBoundary().workSettlementTickets` or runner `workAwaitingSettlement` records; `settleDeferredWork` uses an atomic local `settlementToken`. Persist only host-accepted facts and reconstruct with `acceptedCompletedWorkVertexIds`. `eventKind: 'workCompletionCommitted'` / `'subgraphCompletionCommitted'` observe committed W/C; callback timing remains before commit and seeds synthesize no work event. `getTraversalStopReason` distinguishes pause, preparation and awaiting settlement.
- **Sources and discovery:** Source option keys are `treeDiscoverySource`, `dagDiscoverySource`, and `graphWalkDiscoverySource`. Graph defaults are `rootWorkPrerequisitePolicy: 'honor'` and `undeclaredWorkPrerequisitePolicy: 'none'`; tree-source DAG mode rejects explicit graph dependency policies. Tree sources reject graph metadata. Tree/DAG sources return `vertexResolved` with `resolvedVertexInput.vertexContentInput` or `vertexIntentionallyOmitted`; only prerequisite lookup accepts `missing`. DAG omissions include `omittedVertexIdentity` and `satisfiesWorkAndSubgraphCompletionPrerequisites: true`. Materializers return full `{ dagDiscoverySource, sourceRootIsHiddenEntryHolder: true }` envelopes; pass/spread the whole input. Synthetic entry source parents are null in both parent fields; ordinary tree parents remain non-null.
- **Commands and ownership:** `END_WORK_VISITOR_CHAIN_AND_DEFER_WORK_COMPLETION` is exclusive and ends a work chain. `PAUSE_TRAVERSAL_AT_COMMAND_COMMIT_BOUNDARY` pauses it. Use family deletion commands `DELETE_CURRENT_VERTEX_AND_RESOLVED_TREE_DESCENDANTS` or `DELETE_DAG_VERTEX_WITH_DEPENDENTS_AND_ORPHANED_DESCENDANTS`; standalone tree-store deletion remains `deleteSubtree`. `SKIP_PENDING_CHILD_DISCOVERY_OF_CURRENT_VERTEX` skips pending local slots. `SET_CURRENT_VERTEX_PHASE_CHAIN_STATE` takes `{ phaseChainState }`. Command batching is independent of async concurrency; `maxConcurrentCallbackInvocations` caps CTT callbacks, not host agents. `requestPauseAfterAdmittedCallbacksDrain` is cooperative and cancels no admitted callback.
- **Callbacks, events and registration:** `deliveredEventKinds` filters at delivery, including buffered and deferred settlement records; `admittedVisitorCallbackPhases` snapshots admission for a new chain. Patch fields independently. Callback context is `visitorPhase`; tree/DAG/walking observations use `eventKind`. Shared `visitorCommandCommitTiming` values are `afterEachVisitorCallback` and `afterContiguousVisitorBatch`. Higher `descendingExecutionPriorityWithinGroup` runs first within a group; insertion order breaks ties. Explicit ordered groups own batching. Query methods return detached registration records with shared callbacks/group metadata. Tree callback aliases order generics as `<InputVertexTypes, RewrittenVertexTypes, Phase>`; contexts keep their own declaration order.
- **Observation and identity:** Prefer live read-only views, restricted `VertexHandle.getCurrentVertexView`, `getReferenceIdentity`, and graph `requireVertexId`/`getVertexHandleByIdOrNull`. Standalone `MutableValueReference` reads/replaces through `getReferencedValue`/`replaceReferencedValue`. `Vertex.getMutableChildDiscoveryHints` exposes owned membership; `VertexView.getDetachedChildDiscoveryHints` returns a frozen detached array. Common `createEditableShallowCloneWithContentOverrides` copies membership and retains opaque values. `hasChildDiscoveryHints` is positive and does not establish a structural leaf. Path controls `includeDesignatedRoot` / `includeTargetVertex` default true. Snapshot collections are detached/frozen; caller data and arbitrary IDs retain identity.
- **Diagnostics and revisions:** Milestone constraints point from `waitingMilestone` to `prerequisiteMilestone`. Structural `componentVertexIds` are SCC membership; discovery `cycleWitnessVertexIds` are ordered closed witnesses. Scheduling visit stages, callback counts, W/C progress and runner lifecycle remain separate observations. `ValidatedReusableDagTopology.definition` retains ordered entry/child slots and omissions; `liveVertexSummaries` is only a live-child projection. `mapDagFragmentIds` explicitly maps IDs; composition separates structural links and work prerequisites. `applyDagDefinitionRevisionBatch` validates an ordered batch privately and returns a fresh validated topology plus shallow declaration diff. Old sessions/tickets/callbacks stay local and no completion facts migrate automatically.
- **Walking:** Walking uses its own explicit source protocols and target wrappers. `vertexResolutionMode` selects resolver-with-inline or inline/previously-admitted operation; the first admitted resolution, including omission, wins and rejected links do not seed cache. Observations distinguish `vertexOccurrence`, `admittedEdgeOccurrence`, and `routePrefix`; revisit policy, callbacks and delivery are independent. The default first-admitted policy preserves parallel/back edges. Bounded route modes count root/link reads, admitted target occurrences and hop depth in distinct units. Callbacks are serial; own concurrency options reject. Consumer iterator return pauses; `closePermanentlyAndDisposeSourceIterators` disposes acquired iterators in reverse order. FAILED close rethrows the retained error without repeated cleanup; async closes share a promise. `replaceLimits` replaces the entire previous record and merged validation is atomic. DAG adapter labels are detached; caller edge data retains identity.
- **Objects and output:** Object property records use `propertyKey`/`propertyValue`. Property rewrite requests are `patchPropertyKeyOrValue`, `deletePropertySubtree`, or `keepPropertyAndAssembleCurrentChildren`. The assembly cache is an explicit `hasAssembledValueForVertex`/`getAssembledValueForVertex`/`setAssembledValueForVertex` protocol; assembly options are `{ cacheResult }`. Preserve arrays according to `arrayAssemblyIndexPolicy` and handle duplicate keys through `assembledPropertyKeyCollisionPolicy`. Rewrite output is present/absent tagged and defaults to unknown; `rewriteObjectWithAssertedOutputType` is a caller assertion, and `getFinalOutputResult` requires FINISHED. The combined rewrite helper owns its source.
- **Packaging and removals:** Runner constructors, raw mutable runtime state, normalized inputs and engine paths are private. Use explicit supported entry points and public factories/capabilities. General capabilities default to `TraversalExecutionSnapshot` and preserve family phases. CJS/ESM share declaration and constructor identity. No legacy aliases remain: `$data`/`$childHints`, older `$d`/`$c`, old method names, and old option/literal forms are unsupported. There is no durable checkpoint, storage-provider port, public `planDag`, or built-in LLM integration.

## Commands and validation

```sh
npm ci
npm run check
npm test -- tests/dag-prerequisite-resolution.test.ts
npm run tsfile -- examples/agent-orchestration-example.ts
npm run verify-examples
npm run verify-package
```

`npm run check` covers typechecking, lint, all source tests with 100% coverage, examples, build, packed runtime/type consumers, and benchmark/generator checks. For behavior changes, reproduce the issue with a focused public regression, then run the full check. For documentation changes, execute new/changed examples, verify relative links/anchors and packaged guides, and use the standard check before integration. Do not weaken coverage to pass.

The async runtime shares a state-machine core with sync runners; test affected sync/async and tree/graph families when changing shared behavior; include walking when changing common capabilities/selectors/registration. Preserve arbitrary ID identity and exact error values. ESM and CJS must share constructors, sentinels, namespaces, and declaration identity; verify packed consumers, not just source imports.
