## Scope and boundaries

- **Scope (host vs CTT):** CTT owns generic tree/graph discovery, work/completion dependencies, callback scheduling, traversal lifecycle, diagnostics, and in-memory progress. Keep task types, agent dispatch, business priority/outcomes, attempts/retries, claims, artifact policy, and durable storage in the host. `$data` is opaque caller data; `$childHints` contains opaque discovery hints; Vertex fields and serialization use `$data`/`$childHints`.
- **DAG readiness, W/C and settlement:** Dependency edges and structural child edges are different. Under default `afterWorkReadyChain`, normal `ON_WORK_READY` completion satisfies W; committed `ON_SUBGRAPH_READY` satisfies C. Use `workCompletion: 'externalSettlement'` for host-controlled work, including zero/filtered callbacks; prepare a fresh runner for an eager validated preview, then run and dispatch from `summary().awaitingSettlement` records with atomic generation guards. Preparation freezes topology; run adopts discovery without replay. Dispatch from `advance().workTickets` or enabled pre-work visitors. DAG event kinds `workCompleted`/`subgraphCompleted` are committed W/C observations; callback-before-commit and event-after-commit timing remain. Deferred `workCompleted` events emit on settlement; seeds synthesize no work event. `getStopReason()` distinguishes pause from awaiting settlement. Settlement generations are local symbols; reconstruction uses host-accepted `completedWork` facts.
- **Sources and discovery:** Graph sources default to `rootWorkDependencies: 'honor'` and `dependsOnWorkDefault: 'none'`; express execution dependencies explicitly. Explicit graph dependency policies reject on TreeSource inputs; tree order is preserved. Tree sources forbid graph metadata. Source callbacks use tagged `found`/`omitted` results; only prerequisite lookup accepts `missing`. `MaterializedDagInput` and `materializeDagInputFromRecords`/`materializeDagInputFromRoots` (plus Async counterparts) return `{ traversableGraph, syntheticRoot: true }` envelopes; pass or spread the entire input; `DagDiscoverySource` is the actual protocol. Synthetic entry source parents have both parent fields null; tree parents stay non-null.
- **Commands and ownership:** Explicit sole `DEFER_WORK_COMPLETION` ends a chain early; `PAUSE_TRAVERSAL` pauses it. Deletion commands follow the runner family: `DELETE_TREE_SUBTREE` or `DELETE_DAG_VERTEX_CASCADE`; stored-tree deletion is `deleteSubtree`. `SKIP_REMAINING_CHILDREN` skips pending local expansion; `SET_VISITOR_CHAIN_STATE` accepts `{ state }` for the current phase chain. `commandCommitMode` is independent of async concurrency. `emitEvents` and `visitorPhases` select events/callbacks independently and patch field-wise; all family selectors filter at delivery, including buffered records and deferred settlement events, while callback admission snapshots stay independent. Chain inspection `emitEvents` is historical; top-level `executionOptions` governs delivery. Flat visitors sort by priority before batching; explicit ordered groups own their batching policy. Use family-safe execution capabilities and cooperative `requestPause`; requests drain admitted callbacks without cancellation before acknowledgement. The rewrite helper owns its source.
- **Observation, views and identity:** Prefer `resolveChildHook`, typed object patches, `getResolvedTreeView()`, `getRefId()` and graph `requireVertexId`/`getVertexRefById`; ordinary tree/DAG observations expose canonical VertexHandle/VertexView facets, frozen detached hint/topology collections, and shallow caller payload identity. Tree contexts use `resolvedTreeView`; graph contexts use `resolvedGraphView`/`getResolvedGraphView`. Visitor registration queries return detached records with shared callbacks/group metadata. Rewrite output uses present/absent tagged results and defaults to unknown; `rewriteObjectAs` asserts output and `getOutputResult()` requires FINISHED. Diagnostic edges are original milestone constraints, waiter waits for prerequisite; structural cycle `componentVertexIds` are SCC membership; discovery `cycleWitnessVertexIds` are ordered closed witnesses. `inspectDagMilestones` captures observational milestone snapshots. Inspection uses ready/chain `phase`, chain `state`/`visitorIndex`/`executionOptions`, and request `operation`; graph `visitStage`/`getVisitStageOf` describes scheduling boundaries, separately from callback counts, DAG W/C, and runner lifecycle status.
- **Definitions, fragments and revisions:** Multi-entry definitions use ordered `roots` slots; revision removal is `removeVertexDeclaration`. `PreparedDag.liveVertexSummaries` is a live-child convenience projection; `PreparedDag.definition` preserves ordered slots/omissions; `mapDagFragmentIds` maps fragment IDs explicitly and compose structural links separately from W/C wires. `reviseDag` validates an ordered batch against a private candidate and returns a fresh prepared DAG plus a shallow diff; old sessions, tickets and admitted callbacks remain local and no completion facts migrate.
- **Walking:** Walking uses `GraphWalk`/`AsyncGraphWalk` sources with explicit target wrappers; it does not consume arbitrary tree/DAG sources directly. Walking materializers return actual `GraphWalkSource` protocols and retain source names. Revisit, callbacks and emission are independent. First admitted resolution (including omission) wins; rejected links do not seed cache. Default once preserves parallel/back edges; bounded route modes report summary outcomes. Callbacks are serial; own concurrency options reject. Consumer iterator return pauses; terminal runner close disposes open source iterators in reverse acquisition order. Closing FAILED rethrows the exact retained error without repeated cleanup; overlapping async closes share a promise. Configure `replaceLimits` records replace prior limits records and merged validation is atomic. `GraphWalkDagRelation` labels are adapter-owned/detached; caller edge data retains identity.
- **Packaging and types:** Runner constructors, raw containers/state, normalized options and deep engine paths are private; use public factories, capability interfaces and the explicit supported entry points. Graph ID generics trail T/R (visitor ID follows phase); typed live results require own IDs and public views hide synthetic holders. General execution capabilities default to `ExecutionInspection` and `EmissionKind<Phase>`, preserving family phases. Concrete tree/DAG runners use `TreeDagExecutionInspection`; walkers use `GraphWalkInspection`. Tree callbacks use `TreeVisitor`/`AsyncTreeVisitor`, with structural source protocols and no empty runtime bases.
- **Removed names and non-features:** `$d`/`$c` inputs and accessors are removed; there is no public `planDag`, storage-provider port, durable runner checkpoint, or built-in LLM integration; ordinary runners expose no live mutable store or independent traversal-root predicate. See [docs/migration-api-distinctions.md](docs/migration-api-distinctions.md) for the full canonical-surface checklist.

## Commands and validation

```sh
npm ci
npm run check
npm test -- tests/dag-prerequisite-resolution.test.ts
npm run tsfile -- examples/agent-orchestration-example.ts
npm run verify-examples
npm run verify-package
```

`npm run check` covers typechecking, lint, all source tests with 100% coverage, examples, build, packed runtime/type consumers, and benchmark/generator checks. For behavior changes, reproduce the issue with a focused public regression, then run the full check. For documentation changes, execute new/changed examples, verify relative links/anchors and packaged guides, and use the standard check before integration. Do not weaken coverage to pass.

The async runtime shares a state-machine core with sync runners; test affected sync/async and tree/graph families when changing shared behavior; include walking when changing common capabilities/selectors/registration. Preserve arbitrary ID identity and exact error values. ESM and CJS must share constructors, sentinels, namespaces, and declaration identity; verify packed consumers, not just source imports.

## Documentation upkeep

Keep README concise and autonomous-agent use cases first. Put integration decisions in `docs/agent-workflows.md`, detailed contracts in `docs/reference.md`, and navigation in `docs/index.md`. Keep runnable examples under `examples/`; the example verifier discovers every top-level `.ts` file. Regenerate `docs/api-index.md` with `npm run docs:api` after public declaration changes; the package verifier rejects drift. Update package `files` entries when adding a consumer guide so npm readers can follow relative links. Link repository-only examples/history through GitHub from packaged docs. Preserve existing public section anchors when moving content.

Do not infer publication authorization from test/build commands. Release and external-write actions follow the user's current instructions. Preserve unrelated local changes and never include credentials in examples or logs.
